**Goal:** return geometry-checked stitching-via and corner-cleanup proposals for an AI to compare and selectively adopt through ordinary routing tools, without changing the board.

**Architecture:** add one saved-board planning tool, `plan_route_refinement`, in `pcb_routing` (18 to 19 tools). Generate a bounded deterministic candidate set, validate it against geometry and earlier accepted proposals, and return proposals plus explicit unresolved findings.

**Stack:** existing Rust workspace, S-expression/planar geometry, serde JSON, SHA-256; KiCad Python and CLI only in scratch validation. No new dependency is planned.

**Specification:** `CREATION_RESEARCH.md` §5 Q1; `CREATION_HANDOFF.md` S7 and S5/S6 findings; local ignored `target/creation-research/RESOLUTION_PLAN.md` Step 7 is authoritative for the measurement targets. ## Contract and boundaries

- Required proposal kinds: stitching inside the same net's actual fills on both relevant layers near disconnected pads/islands or an unstitched reference change; perpendicular retermination of an acute T branch; 45-degree chamfers for right-angle pad-exit doglegs. A reference change between different plane nets must never be shorted by a via.
- The tool reads the saved board, sibling project/rules and design intent. It never saves, refills, calls a mutating IPC command, starts Freerouting, or applies a proposal. All successful and structured blocked responses contain `mutated: false`; there is no apply mode.
- Input includes `board`, selected proposal kinds (all three by default), optional exact net filters, bounded candidate/response limits and geometry/search dimensions. Validate every advertised argument and refuse unknown values. Chosen bounds: `max_proposals` 50 (1–200), `max_candidates` 10,000 (1–20,000), `search_radius_mm` 3.0 (0.1–20.0), `grid_step_mm` 0.25 (0.05–1.0), and `chamfer_mm` 0.5 (0.01–5.0). The reference-change distance remains the audit's 3.0 mm threshold unless explicitly supplied identically to both. A deterministic single greedy pass tries the requested chamfer setback and three successive halvings; no random optimization or background iteration. Round proposed coordinates to 1 nm; require an extra 0.01 mm geometry margin beyond resolved clearance. That margin covers the existing 0.005 mm curve approximation on both shapes. Bound input board content to 64 MiB and 50,000 parsed copper/outline objects; bound the plan to 200 proposed copper objects, 20,000 candidate tests and 2,000,000 pairwise clearance checks; exhausted budgets yield partial coverage, not all-clear. Bound responses to 48 KiB and truncate only whole independent proposal groups, with total/listed counts. These choices keep local search within the existing 200-object batch limit and make runtime/output predictable; the matrix must expose any resulting acceptance shortfall.
- Versioned shared plan envelope: `schema_version`, `planner`, `mutated`, `source` (saved state, input hashes and excluded unsaved changes), `status`, `parameters`, `before`, `proposals`, `blocked`, `coverage`, `not_checked`, `truncated` and adoption/verification instructions. Each proposal has a stable ID, kind, reason, affected net/layer/KIIDs, exact original geometry, proposed geometry, ordinary-tool operations, dependencies/conflicts, geometric checks and predicted metric changes. Predictions are not post-refill measurements.
- A complete proposal set is bound to the input bytes, rules, intent and parameters; re-read fingerprints before returning. Changed input refuses the plan. Missing/stale saved fills are not proof of absent copper: stitching must report blocked/unknown when the required copper is unavailable. Saved fill presence cannot prove freshness; state the required refill-and-save precondition and limitation.
- Use full copper envelopes, not center points or raster cells, for clearance and containment. Include tracks, pads, vias, actual foreign-net fills, copper graphics/text, edge/cutout clearance, holes and rule areas on every spanned layer. Reject ambiguous net identity, absent KIIDs, nonfinite geometry, unsupported or underestimated geometry, and unknown relevant rules rather than certify them. Preserve locked copper.
- Reuse `routing_context::Snapshot::read` and `ensure_unchanged` for consistent project/rule snapshots, including duplicate-key checks. Read saved rule minima and class values conservatively, reporting their sources. Reuse `custom_rules::routing_bounds` for its supported unconditional numeric-mm subset; refuse unsupported selectors/constraints. Do not claim the planner reproduces KiCad's general rule engine. The bounded implementation may use conservative class maxima when per-net resolution is not proven. Optional dimensions may increase, never relax, safety minima. Check the coupled constraint `diameter >= drill + 2 * minimum_annular_width` after nanometer rounding; separate maxima do not establish it. Width floors come from board/custom-rule minima and any proven relevant class, not the maximum preferred width of unrelated classes. If the relevant width policy cannot be resolved, return a blocked adoption item rather than silently widening it.
- Preserve widths and every existing same-net terminal attachment during corner changes. Orthogonality at T retermination must be checked directly, including mid-segment junctions that today's acid-trap counter omits. Validate cumulative proposals together, including new-new clearance and overlapping edit ownership. Recompute connectivity/metrics in memory; do not infer electrical improvement merely from a smaller finding count.
- Through vias only, using the actual copper-layer order (2- and 4-layer fixtures). No blind/buried-via support. No S6 plane-policy change, S9 staging, thermal-relief repair, simulation feature work or S11 detector.
- Production adoption is selective: compare against the AI's own design with identical `audit_layout_quality` settings; use existing `route_batch` for creates and `modify_trace` for changes; re-observe identities/state, save/refill, DRC and audit. `route_batch` cannot replace tracks. The plan is not one atomic undo operation and supplies no new automatic apply helper.

## Review focus

The mandatory counterexamples are an oblique midsegment T hidden by the audit, a chamfer that disconnects an unnoticed branch, a through via shorting an intermediate layer, an alleged stitch in a fill void/stale fill, and two individually valid proposals that conflict together. Tests above own each case. Any unsupported feature that can invalidate the safety proof must block the affected proposal or the plan with an explicit reason.
